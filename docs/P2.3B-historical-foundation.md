# P2.3B: local historical data foundation

This opt-in pipeline does not change production realtime or the Tencent Fast Lane.
It supports a two-year *sample pool of local stock behavior*, not a claim that a
single two-year trend is a trading strategy. Pattern discovery, features, strategy
generation, backtesting, and trading are outside this change.

## Data tiers

| Tier | Scope | Retention / purpose |
| --- | --- | --- |
| A | All current A-share symbols: raw daily and 30m | About two years; local swings, drawdowns and later features |
| B | 1m, 5m, 15m | Plan a rolling 60-session 1m window; 120 sessions requires a new capacity gate. Longer 5m/15m is explicit, not an automatic all-market download |
| C | Explicit research/candidate/index symbols | Bounded on-demand deeper minute history at the actual available depth |

The approved 2024-10-01–2026-09-30 Tier A range has 485 exchange sessions.
The separate depth probe starts on 2024-09-01 (504 sessions). Seven SH/SZ equity
and index probes covered that entire window. 920433.BJ's minute history was
shorter. Do not assume all BJ symbols have two-year minute history.

The 250807.1.2 SDK reads 15m/30m from downloaded 5m base bars. The local SDK cache
therefore occupies space in addition to the formal DuckDB; it is not a second
canonical history store. Do not count only DuckDB bytes when planning capacity.

## Formal database

Default: `data/market_history.duckdb` (ignored by Git). There was no pre-existing
DuckDB history database in this repository. Existing JSON caches remain available
to their existing callers; new foundation reads use this database.

Tables: `bars_daily`, `bars_1m`, `bars_5m`, `bars_15m`, `bars_30m`.
Each has symbol, timestamp, trade_date, OHLC, volume, amount, source, provider,
adjustment, quality_status, volume_unit, amount_unit and ingested_at. TIMESTAMP
values are Beijing local time, with this convention also attached to returned
DataFrames. Vendor epoch milliseconds are converted explicitly.

The primary key is `(symbol, timestamp, adjustment, source)`: alternative sources
have separate series. `history_selection` chooses exactly one source per symbol,
period and adjustment. Readers never concatenate sources. Switching an existing
selected source requires a future explicit migration policy; appending a fallback
to an established primary series is rejected.

`history_gaps` records missing observation counts and first/last missing slots per
session. `history_quality_events` retains structural failures and rejected-row
counts. `history_sync_tasks` records each symbol/date-window checkpoint, attempts,
safe error codes and selected source. `historical_calendar` and `history_settings`
persist the verified session window and its provenance.
`history_universe` freezes each job's symbol membership and listing metadata;
`history_sync_events` preserves classified request/storage errors even when a
later retry succeeds. Missing reference listing dates may be enriched only by
explicit XTDC OpenDate metadata, with that provenance recorded.

The foundation backfill is raw only. Direct store reads and writes distinguish
raw/qfq/hfq; an adjusted sequence cannot enter a raw sequence. Raw XTDC volume is
kept in its original units (equity lots; unverified index volume is sdk_native).
Daily fallback adapters use the existing contracts' shares. Unit metadata is
mandatory; do not silently treat lots as exact shares or rescale amount.

## Quality and missing observations

Before insertion, validate finite values, timestamp bounds and grid, duplicates,
ordering, positive OHLC with low <= open/close <= high, nonnegative volume/amount,
trading dates and minute sessions. Reject invalid rows; sort valid rows while
recording reverse input. Duplicate input does not create duplicate database bars.
Resuming a committed window is an idempotent upsert.

Expected observation grids are diagnostics, not an assertion that every stock
must trade at every minute. The SDK's 1m grid includes 09:30 plus 240 regular
minutes. 5m/15m/30m begin at 09:35/09:45/10:00; all include 11:30 and 15:00, never
fill the lunch break. A verified listing date supports EXPECTED_MISSING before
listing. Other missing observations are UNKNOWN_MISSING with reason UNKNOWN.
Do not infer a suspension, halt or no-trade state from missing data. Structural
errors are recorded separately as STRUCTURAL_ERROR. No prices/volume are filled,
interpolated or invented.

The existing AShareTradingCalendar adapter is reused with the verified XTDC
session list. Its built-in 2026 holiday fallback is not extrapolated to 2024/2025.
An unverified calendar range is rejected; the CLI expands the verified calendar
before a later incremental update.

## Sync and recovery

Run from the repository, using the same Python environment as its requirements:

```powershell
python scripts/historical_sync.py initial_backfill --all-a --period 1d --start 2024-10-01 --end 2026-09-30 --job-id p23b-daily-two-year
python scripts/historical_sync.py initial_backfill --all-a --period 30m --start 2024-10-01 --end 2026-09-30 --job-id p23b-30m-two-year
python scripts/historical_sync.py resume --job-id p23b-daily-two-year
python scripts/historical_sync.py incremental_update --all-a --period 1d --end 2026-10-09 --job-id daily-2026-10-09
```

The last command is an example for a later completed session, not a scheduled
job. Do not request unfinished/future bars. The CLI never starts an automation.

Concurrency is one SDK request and one database writer, with up to 50 symbols per
batch. Requests are split into at most 365-day windows (180 days for 1m). Planning
uses a vectorized insert; per-row planning in one large transaction was rejected
after a measured memory-limit failure. Database memory is capped at 4 GB, with
two DuckDB threads. A deployment must provision space for the database, WAL,
temporary files, and SDK cache; the CLI stops at an 8 GiB disk reserve.

Ctrl+C sets cooperative cancellation. `--stop-file PATH` stops after the current
bounded batch when that file exists. Remove that specific stop file before
resuming. `--progress-file PATH` writes an atomic progress snapshot. The history
worker enforces an RPC deadline, terminates a stuck owned process, and reconnects
on the next request. Checkpoints skip DONE work; FAILED work can be retried with
resume. DONE is transport/sync completion, not proof of gap-free data.

Only missing windows are fetched on initial resume. Incremental updates start
after the stored last timestamp (next date for daily), not at the original start.
Older holes remain explicit in `history_gaps`; use a dedicated bounded repair job
for them. A failed symbol does not abort other symbols. Recognized rate limiting
causes immediate exponential backoff before another request.

Daily source preference is XTDC, then the existing Hithink range adapter, then
existing AKShare/BaoStock adapters. Once an available source is chosen for a
series, remaining chunks use it. Minute history has no automatic cross-source
fallback. Missing rows in an established source are not filled from another.

The CLI reads XTDC_TOKEN only from the repository `.env`. The dedicated history
worker suppresses native stdout/stderr and native log initialization before
authentication. No credential value, length, fragment or hash is logged. Errors
are classified into safe codes; location diagnostics omit exception text.

## Local consumer API

```python
from src.market_data.historical_store import HistoricalStore

with HistoricalStore(read_only=True) as store:
    daily = store.get_bars("600498.SH", "1d", "2024-10-01", "2026-09-30", adjustment="raw")
    dataset = store.get_two_year_behavior_dataset("600498.SH", end="2026-09-30")
```

These calls perform no network access. The dataset contains daily, bars_30m,
provenance, and a conservative per-symbol `ready` flag. Quality checks and gaps
remain visible; readiness is not permission to generate or trade a strategy.
Readiness checks the entire requested two-year window against the verified
calendar. Merely having a few locally valid rows cannot mark that window ready.

DuckDB is a single-writer local database. The CLI owns that writer process; do not
open a separate reader process while a backfill holds the write lock. In an
integrated application, expose the shared store through the same owning process.
Scanner feature calculation should batch local reads, not call vendor endpoints
per stock. This change intentionally does not rewire production consumers.
