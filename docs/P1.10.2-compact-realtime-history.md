## 结构与兼容范围

`CompactMarketHistory` 用 symbol index、两个共享的 NumPy float64 矩阵保存 timestamp 和 last_price。每个 symbol 在矩阵中有独立的环形游标与计数；没有逐 symbol 的 Python deque，也不在生产快照路径构造或保留 RealtimePoint。

保留单股实际行情时间是必要的：同一轮全市场快照中的各股时间可以不同，停牌或没有新成交的股票也可能保持旧时间。仅使用一个全市场帧时间会改变其涨速参考时间。因此这里采用紧凑时间矩阵，而不是用请求时间代替单股时间。float64 保留 Python float 的精度，避免 float32 改变四位小数的涨速结果。

- 时间保留范围为 360 秒：5 分钟加 60 秒余量，并保留边界前最近一个点，支持稀疏报价的合法参考。
- `maxlen` 构造参数现在只是初始分配提示，不再截断样本数。采样变密时容量增长，按时间淘汰。
- `speed(symbol, minutes)` 保持原有单位和公式，对逻辑环二分查找 `timestamp <= latest_symbol_time - minutes * 60` 的最近点。
- 相同时间替换价格；较旧时间拒绝；午休前后、跨日使用独立连续交易 session。
- `RealtimeSnapshotBuffer` 是兼容名称。`points(symbol)` 只在单股图表读取时临时构造兼容对象；`prices` 直接读取数值矩阵。
- 历史不再保存 volume、amount、turnover 或完整 row；这些最新值仍在 current snapshot 中。
- LIVE / STALE / CACHED、flash、Top20、SSE、Provider、worker、Router、Scanner 规则、日K服务和 Indicators 均未改写。

## 容量与预算

假定 5,553 symbols，在本机 Python 3.11 的保守对象估算中，一个旧点的对象、属性字典和五个独立 float 合计约 288 bytes。旧 `300` 点设计容量为 1,665,900 个 RealtimePoint；加 deque/dict 容器约 **475.8 MiB**。这是理论估计，不是 tracemalloc 实测，两者不可混用。

1 秒采样下 300 个点仅覆盖 299 秒，不能完整计算 5 分钟。若旧布局覆盖 360 秒余量，需要 361 点/股，仅点对象估算便约 **550.6 MiB**，尚未加入 deque 容器。

新结构每个历史样本只占 16 bytes（timestamp + price）。以下预算含矩阵预留空间及游标、计数向量，不含约 1 MiB 的 symbol/session 索引和模块导入基线：

| 采样间隔 | 稳定点数/股 | 全市场有效数值样本 | 有效数据 MiB | 分配容量/股 | 数组分配 MiB |
|---|---:|---:|---:|---:|---:|
| 1 秒 | 361 | 2,004,633 | 30.59 | 450 | 38.32 |
| 2 秒 | 181 | 1,005,093 | 15.34 | 300 | 25.57 |
| 5 秒 | 73 | 405,369 | 6.19 | 300 | 25.57 |

工程预算：已知 5,553 symbols、1/2/5 秒采样时，历史稳定数组不超过 40 MiB，连同索引目标在 45 MiB 内。300→450 扩容期间旧、新数值数组暂时并存，合计约 64 MiB。更密集的不规则或亚秒采样依时间窗口自动扩容，预算随最高窗口内采样密度变化；不伪装成任意采样频率下固定 40 MiB。容量保留高水位以复用内存。

## 独立进程内存对照

使用 `scripts/compact_history_memory.py`，固定 5,553 symbols、1 秒行情时间间隔。每个实现分别运行独立进程，基线都已导入相同模块。仅生成离线输入，不连接任何行情源。

关闭 tracing 的 RSS 对照：

| 实现 / 帧数 | 有效历史样本 | retained RealtimePoint | 进程 RSS MiB | 相对导入基线 RSS MiB |
|---|---:|---:|---:|---:|
| 旧 / 300 | 1,665,900 | 1,665,900 | 557.09 | 478.72 |
| 新 / 300 | 1,665,900 | 0 | 105.02 | 26.30 |
| 旧 / 420 | 1,665,900 | 1,665,900 | 558.26 | 479.89 |
| 新 / 420 | 2,004,633 | 0 | 117.80 | 39.08 |
| 新 / 840 | 2,004,633 | 0 | 117.85 | 39.12 |

同为 300 帧时，RealtimePoint 减少 **1,665,900 个（100%）**。新结构从第 420 到 840 帧，样本数和数组分配均不再增长，RSS 只增加约 0.04 MiB。其稳定窗口比旧结构更长，而相对基线 RSS 仍减少约 91.8%。

GC 可追踪对象：旧进程约 1,732,224 个（相对基线新增 1,671,451），新进程约 60,770 个（相对基线 -3，属于 GC 跟踪状态差异）。GC 统计不是所有 Python 对象总数，特别不包含普通 float、部分 dict 和 NumPy 原生数据区。历史本身只有四个数值数组及 O(symbols) 索引，不产生百万级 Python 点对象。

另行开启 tracemalloc 的对照在第 420 帧：旧 traced current **387.60 MiB**，新 **39.31 MiB**；tracer 自身额外开销分别约 **613.41 / 1.01 MiB**。开启 tracing 时 RSS 明显受诊断影响，不能与未开启 tracing 的进程混作同一曲线。完整原始数据见 `outputs/diagnostics/p1102-memory-*-traced.json` 和 `*-untraced.json`。

## 全市场复制/引用审计

| 容器 | 保留范围 | 历史全市场 row 复制 |
|---|---|---|
| CompactMarketHistory | 时间/价格数值矩阵、symbol/session 索引 | 无 |
| Feed `_latest_rows` / `_latest_ticks` | 各 symbol 最新 row 与原始 tick | 无逐轮追加 |
| `previous_rows` | 当次 snapshot 调用内，用于差异判断 | 临时复制，函数退出释放 |
| `cached()` / 返回 rows | 调用者的一次视图 | Feed 不将历次返回值追加进历史 |
| SSE `SnapshotBus` | 单个最新 payload；目标股＋Top20 | 不保存全市场历次 rows |
| request diagnostics / SSE sent_events | 有界统计、时间戳与 trace 元数据 | 无全市场原始 tick/row |
| consumer state | 各 symbol 最后 seq 与价格 | 无逐轮历史 |
| 实时页 `realtime_previous_rows` | session_state 中被覆盖的上一份视图 | 无逐轮列表追加 |
| LastValidSnapshot | 最新有效行情持久化 | 不充当内存历史 |
| Scanner `SnapshotHistory` | 既有独立 600 秒扫描历史 | 本轮未改变；不能据此宣称其他内存增长全部消失 |
